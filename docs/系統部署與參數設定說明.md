# 商品上架工作台：系統部署與參數設定說明

本文件說明此專案的設定參數、部署方式、系統架構、上傳與日誌流程，供維運與交接使用。

## 1. 系統功能概要

- 前端：上傳 `xlsm`、解析 `main` / `price_tag`、檢核缺漏、可編輯售價與抽成。
- 後端（Vite middleware）：接收整理後資料、寫入 Google Sheet、保存原始上傳檔、寫入 upload log。
- 健康檢查：啟動時自動檢查 Google Sheet 憑證與表頭讀取；另提供 `GET /api/sheet-health`。

---

## 2. 參數設定

### 2.1 Google Sheet 連線參數

檔案：`src/server/sheetUploadConfig.ts`

```ts
export const SHEET_UPLOAD_CONFIG = {
  cred_path: 'shared/config/xxxx.json',
  spreadsheet_id: 'Google 試算表 ID',
  worksheet_name: '工作表名稱',
  header_row: 2,
  data_start_row: 4,
};
```

參數說明：

- `cred_path`：服務帳戶 JSON 憑證路徑（相對專案根目錄）。
- `spreadsheet_id`：目標 Google 試算表 ID。
- `worksheet_name`：寫入的工作表名稱。
- `header_row`：用來讀取欄位名稱的列（本專案用來對欄）。
- `data_start_row`：資料 append 起始參考列（Google API 仍會 append 到尾端）。

### 2.2 憑證檔放置位置

- 建議放在：`shared/config/*.json`
- 此路徑已在 `.gitignore` 排除，不會被 commit。

## 3. 執行與部署

### 3.1 本機開發

```bash
npm install
npm run dev
```

### 3.2 區網分享（同網路可連）

```bash
npm run dev -- --host 0.0.0.0 --port 5173
```

同網路使用者以你的內網 IP 存取：

- `http://<你的IP>:5173`

注意事項：

- Windows 防火牆需允許 Node.js 或開放對應 port。
- 必須在同一個 LAN / Wi-Fi，且路由器未啟用 AP 隔離。

### 3.3 近正式預覽（建議給多人穩定測試）

```bash
npm run build
npm run preview -- --host 0.0.0.0 --port 4173
```

存取：

- `http://<你的IP>:4173`

## 4. 系統架構

### 4.1 模組結構

- UI 與流程：`src/App.tsx`、`src/components/*`
- Excel 解析：`src/utils/fileParsers.ts`
- 驗證邏輯：`src/utils/validateProduct.ts`
- Sheet 組裝：`src/server/buildGoogleSheetRows.ts`
- Sheet 寫入與健康檢查：`src/server/appendRowsToGoogleSheet.ts`
- API 入口（middleware）：`vite.config.ts`

### 4.2 資料流（上傳到 Google Sheet）

1. 使用者上傳 `xlsm`。
2. 前端解析並產生 `rows`（符合目標欄位）。
3. 前端送出 `POST /api/upload-to-sheet`，內容包含：
   - `rows`
   - `selectedPlatforms`
   - `originalFile`（檔名、size、mime、base64）
4. 後端 middleware：
   - 儲存原始檔到 `shared/uploads/YYYY-MM-DD/...`
   - 呼叫 Google API append 到試算表
   - 寫入 `shared/logs/upload-log.jsonl`

## 5. API 說明

### 5.1 `GET /api/sheet-health`

用途：檢查憑證是否有效、是否可讀取目標 worksheet 表頭。

成功回應範例：

```json
{
  "ok": true,
  "headerCount": 52,
  "worksheet": "上架_PM",
  "sampleHeaders": ["platform", "erp_product_name", "sale_product_name"]
}
```

### 5.2 `POST /api/upload-to-sheet`

用途：保存原始檔、寫入 Google Sheet、記錄 log。

Request body 重要欄位：

- `rows: GoogleSheetRow[]`
- `selectedPlatforms: string[]`
- `originalFile: { name, mimeType, size, contentBase64 }`

成功回應：

```json
{
  "ok": true,
  "appendedCount": 123
}
```

## 6. 檔案儲存與日誌

### 6.1 原始上傳檔

- 路徑：`shared/uploads/YYYY-MM-DD/<timestamp>-<originalName>.xlsm`
- 檔名會進行非法字元清理（Windows 不可用字元會替換為 `_`）。

### 6.2 上傳日誌

- 路徑：`shared/logs/upload-log.jsonl`
- 格式：每行一筆 JSON（JSON Lines）

每筆 log 包含：

- `timestamp`
- `ip`
- `selectedPlatforms`
- `uploadedFileName` / `uploadedFileMimeType` / `uploadedFileSize`
- `storedFilePath`
- `rowCount`

## 7. 啟動時自動健康檢查

系統在 dev server 啟動時會自動執行一次 Google Sheet 健康檢查，終端會顯示：

- 成功：`[sheet-health] OK ...`
- 失敗：`[sheet-health] FAIL ...`

建議啟動後先確認此訊息，再開始給使用者上傳。

---

## 8. 常見問題排查

### 8.1 `sheet-health FAIL`

請依序檢查：

1. `cred_path` 是否正確。
2. JSON 是否為有效服務帳戶憑證（非 placeholder）。
3. 試算表是否已分享給服務帳戶 `client_email`。
4. `spreadsheet_id`、`worksheet_name`、`header_row` 是否正確。

### 8.2 可開網頁但其他電腦連不到

- 確認是 `--host 0.0.0.0` 啟動。
- 防火牆放行對應 port（5173 / 4173）。
- 對方與主機在同一個網段。

### 8.3 上傳成功但表格資料對不上

- 檢查 Google Sheet `header_row` 是否與程式 mapping 對應。
- 檢查 `buildGoogleSheetRows` 欄位組裝規則是否與模板最新欄位一致。
